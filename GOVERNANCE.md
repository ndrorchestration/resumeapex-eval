# Governance and Data Boundary

> **Current-use rule:** ResumeApex Eval is an experimental evaluation repository with its own benchmark/evidence boundary. Historical DGAF protocol numbers, named agent authorities, harmonic parameters, and July 2026 anchors are provenance/context only unless a current exact source re-establishes the narrower claim.

## Repository scope

ResumeApex Eval contains the project-defined Goldcanstaytoday protocol, evaluator implementation, public known-answer fixture, deterministic verification workflow, and related evaluation documentation.

This repository does **not** independently govern DGAF, certify models, or establish DGAF/PDMAL scientific state, authorization, production readiness, or empirical model performance.

## Relationship to DGAF

`DGAF` means **Dynamic Governance Agentic Formation**. `DGAF-Framework` is a related but separate governance/evidence research track.

Current DGAF claims must resolve to the current DGAF source that owns the claim. Historical references such as `v1.0.0-anchor`, `S070`, STRUCT-QA issue numbers, P-xx protocol labels, Amethyst, COLLEEN, or other agent-role labels do not transfer present authority into this repository.

## Sensitive career-data boundary

Real personal resumes, CVs, cover letters, application records, private employer correspondence, identity documents, credential records, and other sensitive career artifacts must not be committed to this source/evaluation repository unless they have been deliberately sanitized for public/repository use.

Use the public synthetic/known-answer fixture for executable verification. Private governed corpora remain outside the public fixture path and must be handled according to their actual storage/access policy.

This rule is **content-based, not filename-based**. Repository code and documentation may legitimately contain words such as `resume`, `cv`, or `ResumeApex`; those substrings do not themselves constitute sensitive personal data.

## Evaluation and evidence rules

- protocol/rubric text is **DEFINED** evidence;
- executable evaluator behavior is **IMPLEMENTED**;
- deterministic known-answer/repeatability checks can support **VERIFIED** claims about the harness behavior they actually test;
- a fixture adapter is not a model and must not be reported as model performance;
- private-corpus or real-model results require their own source-bound empirical records;
- a green workflow is not external benchmark validation, certification, production readiness, or general efficacy evidence;
- cross-repository references do not constitute mutual validation.
